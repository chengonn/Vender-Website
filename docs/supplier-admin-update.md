# 供應商建檔與帳號原型更新

本次直接修改 `C:\vendor\vendor-portal-login\vendor-portal`，沒有修改先前交付目錄。只使用記憶體假資料，不安裝套件、不部署、不寄信。

## 頁面

- `/admin/suppliers`：供應商列表、預建帳號、啟用／關閉。
- `/admin/suppliers/new`：中英文公司與地址、國家、聯繫人、電話、信箱、五項匯款資料、三項帳務聯絡資料、稅籍、備註、管理者設定初始密碼、角色與狀態。
- `/admin/suppliers/[code]`：建檔資料審核，通過／退回（原因必填）。退回後資料修正與重送留待下一次擴充，原型保留唯讀紀錄。
- `/admin/orders`：保留既有帳單審核與忘記密碼站內提示。
- `/login`：只能使用預建公司代碼，不提供供應商自行註冊。未審核通過或關閉的帳號不可登入。首次登入須更換不同且至少 8 碼的示範密碼。

## 已確認與暫定

- 使用者指定：供應商由 Admin 建檔；公司代碼作帳號、角色名稱及啟用／關閉選項、首次登入改密碼。
- 暫定編碼：三個以上英文單字取前三個字首，故 GRAND OCEAN LOGISTICS → GOL0001。少於三個字則取連接後前三字母；不足三碼補 X。同字首流水號累加、不重用、9999 後阻擋。字面「英文前三碼」與 GOL 範例仍有差異，此演算法尚待業務確認。
- 暫定審核：新建待審核，通過且啟用後可登入；同一 Admin 可建檔與審核，正式核准權責待定。
- 暫定驗證：中英文公司名稱、兩碼大寫國家代碼與初始密碼必填；信箱非空時驗證格式。尚未驗證國家名冊、Swift、銀行帳號或稅籍真實性。
- Vendor 可進入供應商假資料工作台；Admin／Accounting／CS／OP 先保存角色名稱，不將新建的這些帳號授予管理權限。管理端仍使用獨立 ADMIN-DEMO 示範入口，正式 RBAC 尚未實作。
- 忘記密碼仍依前次明確澄清採站內提示。此次貼文又出現 MAIL 給管理者，記為待釐清差異，不實作寄信。
- 「後台顯示现行密碼」與原 passwordHash 規格衝突尚未裁決；本頁不顯示現行密碼。稅籍與密碼為獨立欄位，不以稅籍自動當密碼。
- 新建帳號、更換後密碼、審核狀態皆只留於同頁籤 React 記憶體。重新整理會重設；離開示範保留供應商資料以便切换帳號體驗。請勿輸入任何真實密碼、供應商或銀行資料。
- 供應商工作台仍使用共同的既有訂單假資料，尚未實作依公司隔離、正式 Session 或路由保護；首次更換密碼是登入流程展示，不是後端安全機制。
- 24 小時申請修改規則沿用前次暫定設定。

## 操作

1. ADMIN-DEMO / Demo1234! 登入，選擇「供應商管理／建檔」。
2. 建立假供應商，記下生成公司代碼與自行輸入的示範初始密碼，送出並通過建檔審核。
3. 按「離開示範」，用該公司代碼與初始密碼登入，完成首次密碼更換。
4. 預建供應商為 DOL0001 / Demo1234!，首次登入也須更換。
