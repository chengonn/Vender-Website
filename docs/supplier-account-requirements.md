## 5. 密碼流程調整建議（未定案）

保留「管理者建立帳號、管理者協助忘記密碼」的操作方向，建議調整為：

1. 管理者建帳後，系統提供一次性、有期限的啟用／設定密碼連結，供應商自行設定密碼。
2. 若業務選擇臨時密碼方案，臨時密碼的產生、交付、有效期及首次登入強制更換需另外定義；不以可取得的稅籍資訊預設密碼。
3. 忘記密碼 → 管理者收到申請 → 核實帳號與接收者 → 系統將一次性重設連結寄到已核實的帳號信箱 → 供應商自行設定新密碼。
4. 後台只顯示帳號狀態、是否完成啟用／改密碼及重設操作，不顯示現行密碼。登入密碼只保存安全雜湊，Audit Log 不記錄密碼內容。

這是替代提案，尚未取代使用者原案。一次性重設連結需隨機、單次使用並設到期時間；密碼重設通知不包含密碼。依據：[OWASP Forgot Password Cheat Sheet](https://cheatsheetseries.owasp.org/cheatsheets/Forgot_Password_Cheat_Sheet.html)。密碼以安全雜湊保存，參考：[OWASP Password Storage Cheat Sheet](https://cheatsheetseries.owasp.org/cheatsheets/Password_Storage_Cheat_Sheet.html)。

## 9. 忘記密碼流程澄清（2026-09-07）

使用者明確補充：忘記密碼於內建系統處理；使用者點擊後，Admin 頁面提示該 user 忘記密碼，之後由 Admin 另外透過 Email 提供「之前現行的密碼」。

- 已確認的通知方向：系統內建立供 Admin 查看處理的忘記密碼申請／提示；不是系統先 MAIL 給 Admin。此補充更新前次通知路徑。
- 供應商與 Admin 各自使用自己的頁面；「到 Admin 頁面提示」按管理端收到申請理解，不表示將供應商導向管理端或給予 Admin 權限。
- 使用者要求的後續動作：Admin 在系統外另外寄信，內容為現行密碼。此處如實保留要求，不自行改成重設已獲同意。
- S05／S06 的密碼處理衝突仍未裁決：原規格 passwordHash／Argon2 只保存不可逆雜湊，無法從該資料還原現行密碼。若需查回，將涉及另行保存可還原的密碼，與原規格設計不同；系統於內部運行不會改變此技術限制。
- 建議但尚未接受的替代流程：Admin 收到站內申請後執行重設，提供一次性重設連結，或經確認的臨時密碼；使用者自行設定新密碼。不得把此建議寫成使用者已確認。
- 尚待定義：未登入者如何標識帳號、Admin 如何核實申請者及收件信箱、申請重複與處理狀態、提示可見的管理者範圍。站內通知不代表已驗證申請者身分。
- 未實作功能、未建立或取得密碼、未寄信。原本「忘記密碼必須先以 Email 通知 Admin」的相依性已解除；其他啟用／重設 Email 範圍仍視最後方案而定。
